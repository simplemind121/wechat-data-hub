# 004 来源采集与 Odoo 草稿桥接

日期：2026-11-20。0.3通用文件归档继续作为唯一入库路径，新增采集端只负责交付授权来源与可重试收据。

- 个人微信从已导出文件开始，不嵌入非官方客户端提取/密钥/注入代码。外部项目只参考公开接口形态，没有复制源码。
- 企微使用独立官方Finance C ABI适配，标准库ctypes绑定；仅处理企业自身存档信封与自身RSA私钥。官方库由部署管理员从腾讯获取，不重分发第三方仓库中的二进制。ABI对照公开接口；官方SDK下载403和未实号验证均保留为限制。
- httpx从AI可选依赖移动到核心依赖，以支持采集客户端和Odoo适配；版本约束和锁定版本沿用0.3，不新增另一个HTTP客户端。ctypes、sqlite3、zipfile为标准库；RSA解密复用核心cryptography。
- 采集凭据哈希入库，绑定来源和管理员身份；只有指定collector端点接受Bearer，不替代浏览器登录。游标代表归档持久化，不代表全量历史完整或规范化完成。
- Odoo普通create无法保证“已创建但响应丢失”后的安全重试，因此提供独立wdh_bridge模块，在同一Odoo事务里预留唯一键、创建资料或草稿并保存远端ID；无桥接不自动降级创建。外部模块为本工程原创，声明LGPL-3，需独立实例验收。
- 实写默认关闭；每条投递复查证据/业务许可/实例/审批人，数量是管理员明确选择的草稿参数，不从MOQ推定。恢复后未完成外部任务取消，采集凭据撤销。

WxJava的完整存档接口用于选型参考；当前Python后端采用直接官方ABI适配，避免增加Java服务。官方共享库可用性、平台和原生依赖须按真实部署重新验证。
