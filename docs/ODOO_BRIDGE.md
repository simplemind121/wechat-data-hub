# 经批准的 Odoo 草稿投递

0.4 增加持久 outbox 和配套 Odoo19CE 模块 wdh_bridge。真实实例仍未提供，部署/权限和真实写入回读为 BLOCKED；协议测试不能替代实例验收。

1. 将 integrations/odoo_addons/wdh_bridge 放入**获授权测试实例**的 addons_path，更新应用列表并安装。模块依赖base；采购/销售/产品/CRM按使用目标安装对应业务模块。
2. 使用专用集成用户，授予“WDH approved draft bridge”组及实际业务模型所需读/创建权限；不使用超级管理员。桥接不 sudo，不绕过原有访问规则。整个系统固定使用该集成用户；换用户前核对历史绑定。
3. 在主应用的私有 .env 配置 ENABLE_ODOO=true、ODOO_URL、ODOO_DATABASE、ODOO_USERNAME、ODOO_API_KEY。先在设置执行只读握手。投递还需 ENABLE_ODOO_WRITES=true，默认关闭。
4. 在业务实体逐字段核对证据并批准。点击“配置 Odoo 草稿投递”，选择目标。客户/供应商、产品优先查询并关联已有资料，也可明确选择新建。采购/销售草稿需选择已存在的合作方、产品变体、币种、单位，单独填写本次草稿数量；MOQ不会自动变成订单数量。
5. 先预览，再批准入队。后台投递并读取远端ID、草稿状态、合作方、币种、行产品/单位/数量/单价。币种须与源证据一致，回读不符进入失败状态，保持原请求键供核查。当前单实体仅一条草稿明细，不自动合单。
6. 在设置查看投递记录。超时自动沿用同一请求键重试；永久错误或重试耗尽后，修复配置、确认远端情况，再人工批准重试。

远端模块在同一数据库事务里保留唯一请求键及目标创建结果。先预留键，再创建目标；崩溃/超时后同键同内容返回原记录，不再次创建。同键不同内容拒绝。只有该模块在实际实例通过安装、并发/超时与权限验收后，才能确认该实例的幂等保证。普通create API不能提供这个保证，因此缺桥接模块时不降级盲目创建。

投递前重新检查管理员、实体审批、业务会话许可、证据快照和目标实例；已有请求变更映射会拒绝。恢复备份时未完成的外部任务取消，需要管理员重新批准重试，避免恢复后意外重放。桥接不修改或删除已有业务记录，不调用确认、批准、发送或付款方法；关联已有资料只读取。每个批准实体/目标模型/实例最多一个创建请求。

本轮只运行了标注为合成的 HTTP 协议替身，包括远端创建后丢失响应、重复入队、映射变更、撤销业务许可、显式数量和回读检查。官方Odoo19源码已核对 product_uom_id 字段及Constraint接口；没有把阅读源码表述为真实安装成功。

已入队请求的映射不可直接改写，避免远端已创建却响应丢失时产生第二份草稿。当前尚无自动安全修正映射功能；字段选错需先由管理员核查远端并人工处理，再进行新的业务审批。
