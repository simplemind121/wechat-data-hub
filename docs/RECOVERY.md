# 升级与回滚边界 · 初始开发切片

当前迁移为 `0001_bronze`。升级命令为 `make migrate`，不会自动创建演示业务数据，不在 API 启动过程中 create_all。迁移文件不依赖可变 ORM metadata。

**自动 downgrade 禁用**：初始迁移的反向过程会删表，因此显式抛错。未实现/未演练加密备份恢复，不可宣称本版本已满足灾备要求，不能作为生产存储使用。

未来生产升级流程：停止写入和 worker → 加密备份 PostgreSQL、CAS 原件和配置恢复信息 → 在隔离目标验证备份哈希和行数 → 升级 schema/镜像 → 健康检查和只读检索核验 → 恢复写入。

回滚预案：保留发生问题的数据库与原件，不在原实例删表或覆盖备份；在独立数据库/新卷恢复已验证备份并匹配旧镜像，核对对象 SHA-256、行数和审计后切换连接；需执行会替换或销毁真实数据的动作时另行明确授权。当前尚未完成这些操作或演练（WDH-061 TODO）。
